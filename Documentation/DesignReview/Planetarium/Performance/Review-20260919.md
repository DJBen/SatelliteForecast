# iPhone planetarium performance review — September 19

Captured Metal System Trace + Time Profiler for 99.885 seconds, process 4937,
iPhone18,4 / iOS 27.0. This is the installed Debug build from before the later
pole/leveling fixes, with profiling overhead. No optimization changes were made
as part of this review.

## Findings

- Renderer explicitly requests 30 FPS. Interior one-second display surface counts
  range 28–31, predominantly 30; these are compositor surface swaps, not a
  per-gesture FPS benchmark.
- 2,975 distinct app GPU frame identifiers. Per-frame envelope across app depth-0
  GPU intervals: median 6.27 ms, p95 14.42 ms, max 51.33 ms. Envelope includes gaps
  between intervals and must not be read as pure GPU busy time or input latency.
- App fragment intervals: median 5.32 ms, p95 12.02 ms. Vertex median 0.064 ms.
  Fragment shading dominates GPU execution. This capture does not isolate
  individual shader costs, so attributing it specifically to water is premature.
- Main-thread Time Profiler sample weight: 39.672 seconds over the capture.
  Inclusive GraphHost.flushTransactions stacks: 21.620 seconds (~54.5% of
  main-thread sample weight). Framework inclusive stacks overlap and cannot be
  added together; this is not 21.6 seconds of UI hangs.
- updateStarRegion inclusive: 4.784 seconds; visibleFaintStars: 2.778 seconds;
  setFaintStars: 1.689 seconds (nested, not additive). Star GPU-instance conversion
  alone appears in 1.209 seconds of inclusive samples.
- Source confirms every pinch forces star filtering/conversion/upload; catalog
  cells are already spatially partitioned but GPU star instances are reconstructed.
  The whole PlanetariumView observes the controller, including frequently
  published bearing and field-of-view changes.

## Prioritized improvements

1. Test a 60 FPS interaction target; retain a lower idle/thermal target if needed.
   The trace suggests headroom but does not prove sustained 60 FPS.
2. Isolate high-frequency bearing/selection/time updates into small views; avoid
   publishing renderer-only field-of-view changes to the entire screen. Avoid
   rebuilding the full time card and glass toolbar on camera motion.
3. Cache star GPU instances and magnitude tiers. Refresh cell membership only
   when the visible region/tier actually changes; reuse safe in-flight buffers.
   Preserve overscan and correctness when zooming outward.
4. If GPU p95 is still too high, profile individual shaders, then consider rendering
   only the diffuse sky/water at reduced resolution while retaining native-resolution
   stars, Moon, planets, lines, and UI. Do not blur the whole planetarium.
5. Repeat the same interaction sequence with an optimized, symbolicated build
   before reporting production FPS or before/after gains.
